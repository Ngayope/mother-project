# コミュニティの設計（ハブ）

設計手順（09の原則）：役割を定義 → 本質 → 形。

## 1. どの設計思想に奉仕するか
設計思想4「人と交わす」。一人で作った意味はもろい、交わすとしぶとくなる（理論4節）。幸せの中心＝人。

## 2. 役割（本質的な目的）
安心ではない（安心は手段）。本質的な目的は：
**自分が作った意味・自分の人生を、人と交わすことで、しぶとくすること。**
一人の納得は内側が揺れたら崩れる。誰かと交わして外に痕跡が残ると崩れにくくなる。

普通のSNSとの根本的違い：SNSはつながり・承認・注目が目的になり人を画面に縛る（A-5違反）。比較・いいね中毒・承認の奪い合い＝ユーザーが降りたかった「社会の摩擦」。持ち込んだら台無し。

## 3. ハブであること（最重要の構造）
交わすのは日常の断片でなく、**他の機能で生まれた「自分の人生の発見」**。
- あかりとの会話で見えた自分（「あ、自分ってこうなんだ」）★いちばん発見が生まれる場
- 図鑑で見えた傾向
- 感謝の木に実ったあったかいこと
- 行動で試したこと／選び直した人生の問い
持ち寄って交わすから、中身が「自分の人生そのもの」になり、しぶとくする、が本当に起きる。
→ コミュニティ＝各機能の上に乗る結節点（ハブ）。各機能の発見がハブを通して外に出て確かになる。

## 4. 二層構造（近くの輪・遠くの気配）
ユーザーの指摘：いろんな人がいると分かる設定にしたい（最終的にグローバル）。ただし「つながるため」ではない。
→ 二層に分ける。

- **近くの輪**（少人数・顔が見える・交わす）：自分の発見を置き、受け取り合う。比較・承認競争が起きにくい。＝「交わして、しぶとくする」場。
- **遠くの気配**（世界中・顔は見えない・存在を感じるだけ）：世界に、同じように自分の人生に向き合う人がこんなにいる、と感じられる。つながらない。けれど「自分だけじゃない」と感じる。
  - 目的：つながるためでなく、一人じゃないと感じるため。孤独が薄れる。
  - 理論的裏づけ：世界に同じ人がいると分かることは、交わさなくても「自分のこの感じは自分だけじゃない」という外の証拠になり、しぶとくする。
  - 形の例：今この瞬間、世界の何人が自分と向き合っているか／同じ問いに向き合う人の数／遠くの誰かの（匿名の）ひとことが、ふと流れる。顔・名前・序列は出さない。

## 5. 構造（双方向）
1. 各機能（会話・図鑑・感謝・行動・問い）で発見が生まれる
2. 自分から能動的にハブへ持っていける（能動）／お題に応えて置く（受動）
3. 誰かが受け取る（評価でなく受容・共鳴）
4. 受け取られて、発見が外にも確かに在るものになる＝しぶとくなる
5. 人の発見を受け取ると自分の機能に跳ね返る（双方向）
→ 各機能の中に「ハブへ持っていく」入口を置く。

## 6. 安心は土台（目的でなく手段）
自分を人の前に出すには安心が要る。安心＝次の三つがない状態：
- 比較されない（数・序列・人気を出さない）
- 否定されない（受容だけ。攻撃の通路を作らない）
- 義務じゃない（反応しなくていい、いつ抜けてもいい）

## 7. 要素の判定基準（一律禁止でなく「安心・目的に資する形か」一本）
丸ごと禁止しない。安心/目的を壊すなら入れない、支えるなら形を変えて入れる。
- いいね（数で競う）→ NG。「受け取った／あったかい」の受容サイン（数を出さない）→ OK
- フォロワー数・人気可視化 → NG（序列）／「また読みたい」と静かにつながる → OK
- 無限フィード → NG（縛る）
- 不特定多数への発信（注目集め）→ NG。ただし「遠くの気配」（顔なし・存在だけ）は別物としてOK
- お題に各自が自分のことを置く（比較軸がない）→ OK

## 8. 全体とのつながり（ふんだんに）
- 図鑑の交換（見せ合う／プロフィール帳交換）
- あかりが人と人の間に入る（緩衝材）
- 感謝（あたたかい木）接続：支え/支えられたことが木に実る。循環が人の間で回る
- 傾向（図鑑）で気の合う人がゆるく見つかる（比較でなく「似てるかも」「学べるかも」）
- 応援する／される
- コミュニティの顔は妹ひかり（あかり＝一対一・内側／ひかり＝みんなの場・外へ広げる）

## 9. 形（役割を満たす最小）
- 近くの輪（少人数・顔が見える）＋ 遠くの気配（世界・顔なし）
- お題に応えて置く（受動）＋ 自分から発見を置く（能動）
- 反応は受容（数で競わない、評価でない）
- 各機能（会話・図鑑・感謝）から持っていける動線
